# Yee 4.3 安装说明

| 文件 | 说明 |
|---|---|
| `yee-4.3.0-py3-none-any.whl` | Yee 4.3.0 安装包（1,085,091 字节，sha256 `2d0895855e7258de81727f4849f464dbe4376c431ee7dd10fd1bcee337a5c9d0`） |
| `install.sh`、`yee_install.py` | 一键安装脚本（只用 bash 与 Python 3.8+ 标准库） |
| `安装说明.md` | 本文件 |
| `mtp_bench/`、`strata/` | llama.cpp MTP 测速工具、strata 引擎的召回补丁脚本，只在对应基座上用，Mia 方案用不到 |

## 0. 任何部署：先看诊断，再安装

不管是什么基座、单机还是集群，都先跑一次诊断：

```bash
bash install.sh --check      # 只看诊断，不写任何东西
```

它会扫本机进程、docker 容器，并列出每个实例的结论（可加速 / 要改参数 / 要打补丁 / 不支持）和可复制的改动命令。要覆盖别的机器或集群，加参数：

```bash
bash install.sh --check --hosts <节点列表>    # 逐台 ssh 过去查
bash install.sh --check --k8s                # 查 K8s 里的实例
bash install.sh --check --url http://<地址>:8000
```

诊断也可以单独跑：`python -m yee doctor`（用法与退出码见包内文档 `deploy.md`）。

装：

```bash
bash install.sh                    # 按诊断结果装到各目标（容器、多机都算）
bash install.sh --hosts <节点列表>   # 多台机器都装
bash install.sh --restart          # 装完重启服务并做健康检查
```

`--restart` 对 docker 目标会逐个 `docker restart`；其它服务需要你自己用原来的方式重启，然后重跑一次诊断确认。补丁类引擎（llama.cpp、strata、Maya、mlx-serve、cuteafd）不自动重编，诊断报告里会给出对应的补丁与构建命令。

## 1. 这个版本做什么

- **部署诊断**：`python -m yee doctor` 认得 15 个引擎，看得出每个实例现在能不能加速、要改哪个参数、要打哪个补丁，结论直接给可复制的命令。
- **所有加速开关默认打开**：跨请求召回（采样请求也用）、KAD 逐请求草稿数、热专家验证预算（p=0.9，启动即启用）、逐请求 conf（vcap）。不需要设任何环境变量。
- **不限制启动参数**：块长、并发、EP、MoE 后端都按你原来的配置运行，Yee 不改。在 SGLang Mia DSV41 镜像里，Yee 从启动命令读出块长（`--speculative-dspark-block-size`），自动补上与块长配套的 `DSV41_VERIFY_CAP=conf:0.1`、`DSV41_VERIFY_CAP_STRIDE=块长+1` 和 `SGLANG_DSPARK_FOLDED_SAMPLING=2`；你已经设了的值不动。
- **多机一致性检查**：每个 TP rank 都装了同一版本 Yee，才启用召回广播和热专家验证预算；有机器没装或版本不同时，所有 rank 一起关掉这两项，服务照常运行，日志里写明是哪几个 rank。以前只在 head 上装、worker 没装时，召回统计停在很小的 `steps` 不再增长、服务卡住，就是这种情况。

## 2. 一键安装：MiaAI dsv41-4x-spark（多台 DGX Spark）

前提：在 head 宿主机上，用平时运行 `./start-tp4.sh` 的那个用户操作（Yee 装在这个用户的 `~/.cache` 下，容器里就是 `/root/.cache`）；head 能用 `.env.tp4` 里的 `SSH_IDENTITY` 免密 ssh 到每台 worker（与 `start.sh` 相同）；有 `python3` 和 `docker`。

```bash
unzip Yee-4.3.zip && cd Yee-4.3
bash install.sh --check       # 只检查，不写任何东西
bash install.sh --restart     # 安装 + 重启 + 健康检查 + 冒烟；失败自动回退
```

`--check` 最后一行是「检查通过，可以安装」再继续。脚本做的事：

1. 自动找方案目录（当前目录、脚本上级目录、`/var/tmp/mia/*`、`~/*`、`/opt/*` 里同时有 `start.sh` 和 `.env.tp4` / `.env` 的目录）；找到多个时用 `--recipe <方案目录>` 指定。
2. 读 env 文件得到 worker 列表、镜像和端口，逐台测 ssh，读镜像自带的 `PYTHONPATH`。
3. 把 Yee 装到**每一台**机器的 `~/.cache/yee43/`（head 和全部 worker），装完逐台核对 sha256；上一版保留为 `yee43.old-<时间>`。
4. 镜像里的 `/opt/dsv41/adapter/verify_cap.py` 是补丁所基于的原件时，放入逐请求 conf 的两个文件，并在 head 的 state 目录写控制文件 `vcap_ctl.json`（`{"mode": "adapt"}`；已有控制文件则保留）。不是原件就不放，其余照常。
5. 备份 env 文件为 `<env 文件>.bak-yee-<时间>`，在末尾追加一段标记块，只有一行：
   ```
   # >>> yee 4.3.0 (install.sh) >>>
   EXTRA_CONTAINER_ENV="$EXTRA_CONTAINER_ENV PYTHONPATH=/root/.cache/yee43:<原来的 PYTHONPATH> YEE=1"
   # <<< yee 4.3.0 <<<
   ```
   原来 PYTHONPATH 里旧的 Yee 目录（`/root/.cache/xy_yee*`、`/root/.cache/yee*`）会被去掉；以前设的 `YEE=0` 被这里的 `YEE=1` 覆盖。写完用 bash 重新读一遍核对，不对就恢复备份。
6. `--restart`：`./start-tp4.sh stop`，后台起 `./start-tp4.sh serve`（日志在方案目录 `yee-install-<时间>.log`），等 `/health` 返回 200（最多 40 分钟，`--timeout-min` 可改），发一个 16 token 的请求冒烟，再从 head 容器日志里摘出 Yee 的启动行。启动失败或冒烟失败时恢复 env 备份、按原配置重启，退出码 3。

退出码：0 成功；1 检查或安装出错（没有改动 env 文件）；2 服务已起来但 Yee 自己关掉了（日志里有 `rank check off`，原因会打印出来）；3 重启失败且已回退。

| 参数 | 作用 |
|---|---|
| `--check` | 只检查 |
| `--restart` | 装完（或卸载完）重启并验证 |
| `--uninstall [--purge]` | 删掉 env 文件里的标记块和安装时写的 vcap 控制文件；`--purge` 再删各台的安装目录 |
| `--recipe DIR` / `--env-file FILE` | 指定方案目录 / env 文件（`--restart` 只支持方案自己的 env 文件） |
| `--no-vcap` | 不放逐请求 conf |
| `--yes` | 不询问（在终端里运行时，写 env 和重启前会问一次） |
| `--mode pip` | 强制走第 4 节的单机安装 |

已经开着的旧版 Yee（例如以前手工放的 `/root/.cache/xy_yee31`）不用先删：标记块里的新 PYTHONPATH 不再包含旧目录。env 文件里以前显式写的 Yee 变量（`DSV41_RECALL_DIR`、`YEE_EXPERT_BUDGET=0` 之类）会覆盖 4.3 的默认值，`--check` 会把它们列出来，需要时手工删掉。

## 3. 怎么确认生效

```bash
docker exec dsv41-head python3 -m yee config            # 每个开关的值和来源：env / default / off
docker logs dsv41-head 2>&1 | grep -E '^\[(yee|recall|yee-eb|yee-kad)\]' | head -40
```

应当看到：

| 日志 | 含义 |
|---|---|
| `[yee] 4.3.0 plan: ...` | 部署诊断结论：能不能加速、要改什么 |
| `[yee] effect: ...` | 运行中的效果判定（每 `YEE_EFFECT_S` 秒一行，默认 600） |
| `[yee] 4.3.0 defaults: RECALL_ACCEL=1 ...` | 默认值已补上（只列出这次补的项） |
| `[recall] patched ...`、`[recall] DSpark proposer wrapped ...` | 召回钩子已装上 |
| `[recall] rank check on: 4 ranks` | 4 个 TP rank 都装了同一版本，召回启用（第一个请求时打印） |
| `[recall] steps=... landed=... errors=0` | 每 30 秒一行，`steps` 随请求增长，`landed` 是召回落地的 token 数 |
| `[yee-eb] rank check on: 4 ranks`、`[yee-eb] armed geometry E=384 ... armed:1` | 热专家验证预算已启用 |
| `[verify_cap] armed (conf:0.1)` | conf 截断已打开（Mia 自己的日志行） |

召回只对和以前内容重复的部分有用（同题重问、改写、代码编辑、RAG 摘抄、长文复述）。以新写文章、新写代码为主的业务，即使 qhash 命中率不低，每次命中也只接受十几个 token，整体提升很小，速度主要来自投机头本身；这时运行日志的 `[yee] effect: E2` 行会直接写明，并列出投机头和并发这一侧可以改的参数（规则见包内 `deploy.md` 第 5、8 节）。

## 4. 其它机器：单机 Python 推理服务

SGLang、vLLM（V2 runner）、TensorRT-LLM、LMDeploy、mlx-lm、transformers 等：在服务所用的 Python 环境里

```bash
bash install.sh               # 找不到 Mia 方案目录时自动走这一步
# 等价于：python3 -m pip install --upgrade yee-4.3.0-py3-none-any.whl && python3 -m yee install-hook
```

之后从这个 Python 启动的服务都会自动加载 Yee，开关同样默认打开。各基座、各加速头的支持情况：`python3 -m yee bases`；用 `python3 -m yee doctor` 检查当前引擎版本是否匹配。卸载：`bash install.sh --uninstall`（`yee uninstall-hook` + `pip uninstall`）。

## 5. 开关一览（4.3 默认全部打开）

| 开关 | 默认 | 关闭方法 |
|---|---|---|
| `YEE`（`RECALL_ACCEL`）召回总开关 | 1 | `YEE=0`：整个 Yee 都不加载 |
| `RECALL_ACCEL_NONGREEDY` 采样请求用召回 | 1 | 设 0 |
| `RECALL_ACCEL_GIB` 召回记录容量 | 0.25（GiB） | 改数值 |
| `RECALL_ACCEL_INDEX_DENSITY` 召回索引密度 | 1 | 改数值 |
| `YEE_KAD` 逐请求草稿数 | 1 | 设 0 |
| `YEE_EXPERT_BUDGET` 热专家验证预算 | 1 | 设 0；不重启时把控制文件 `yee_expert_budget.json` 写成 `armed=0` |
| `YEE_EXPERT_BUDGET_P` 每步保留的路由权重比例 | 0.9 | 改数值，0.95 更保守 |
| `YEE_NOTICE` 启动与运行中的 `[yee]` 提示 | 1 | 设 0 |
| `YEE_EFFECT_S` `[yee] effect:` 行的间隔秒数 | 600 | 改数值 |
| 逐请求 conf（vcap） | adapt | 控制文件写 `{"mode": "legacy"}` 或删掉，不用重启 |
| `VLLM_D_RECALL` / `_NONGREEDY` / `_KAD`（vLLM） | 1 | 设 0 |

单项关闭时把变量写进标记块那一行，例如 `EXTRA_CONTAINER_ENV="$EXTRA_CONTAINER_ENV PYTHONPATH=... YEE=1 YEE_EXPERT_BUDGET=0"`，再重启。

热专家验证预算只在 Mia 的 `moe_b12x_next` 确定性路径上起作用（`DSV41_MOE_B12X_NEXT=1`、`DSV41_MOE_B12X_NEXT_DETERMINISTIC=1`、`EP_SIZE=1`）；别的 MoE 路径上它不介入，日志里没有 `armed geometry`，其余加速照常。4 台 DGX Spark 实测这条路径上 p=0.9 合计吞吐 +17.3%（并发 8 时 new 类 +22.5%）。

## 6. 关闭与卸载

- 单项：见第 5 节。
- 整体关闭但保留安装：标记块里的 `YEE=1` 改成 `YEE=0`，重启。
- 卸载：`bash install.sh --uninstall --restart`；连安装目录一起删加 `--purge`。也可以直接用安装时的备份：`cp <env 文件>.bak-yee-<时间> <env 文件>` 后重启。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| `--check` 报某台 worker 连不上 | 用 `.env.tp4` 里的 `SSH_IDENTITY`、`WORKER_USER` 手工 `ssh` 一次，确认免密；`start.sh` 本身也要求这一点 |
| 诊断说某个实例「要改参数才能加速」 | 按报告里那几行可复制命令改，改完重跑 `bash install.sh --check` 或 `python -m yee doctor` |
| 日志里 `[recall] rank check off: ranks 1,2,3 ...` | 这几个 rank 所在的机器没装 4.3：重新 `bash install.sh --restart`，它会装到每一台 |
| `[recall] steps=` 一直不涨 | 先看有没有 `rank check on`；没有请求进来时 `steps` 本来就不涨 |
| `python3 -m yee config` 显示某项来源是 env、值是 0 | env 文件或启动脚本里还留着以前显式设的值，删掉后重启 |
| `--check` 说「不放 vcap」 | 镜像里的 `verify_cap.py` 与补丁所基于的版本不同，跳过这一项是预期行为，其余加速照常 |
| 没有 `[yee-eb] armed geometry` | MoE 不在 `moe_b12x_next` 确定性路径上，见第 5 节最后一段 |
| `--restart` 退出码 3 | 已自动回到安装前的 env 并重启；把方案目录里最新的 `yee-install-*.log` 和 `docker logs dsv41-head` 的最后 200 行一起反馈 |
